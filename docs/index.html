The problem

Every AI tool has its own config file, its own memory, its own version of you.

✗ Without config-ai

MCP servers defined in every tool. Writing style re-explained every session. New tool = start from scratch. Preferences drift.

✓ With config-ai

One mcp.json, symlinked everywhere. One knowledge base every tool reads. New tool = run setup. Preferences stay canonical.

How it works

Symlinks at the OS level. No plugins, no sync services, no runtime dependencies.

What's inside

Everything an AI tool needs to know about you, in one place.

🔌

Unified MCP servers

Dual-key mcp.json works with both "servers" and "mcpServers" conventions. Add a server once.

🧠

Portable knowledge base

Your identity, writing voice, preferences, and team — in versioned markdown. Every tool reads the same source of truth.

🔗

OS-level symlinks

No plugins or sync. The OS handles redirection. Tools don't know they're sharing — and don't need to.

🎓

Guided onboarding

An AI skill walks you through filling in your knowledge files step by step. Setup takes about five minutes.

📐

Maturity model

Prompt → Skill → Agent. Start simple, promote when complexity is earned. No premature abstraction.

🔄

Git-native updates

git pull to get new agents, prompts, and MCP servers. Your knowledge files stay untouched.

Tool compatibility

Automatic for tools with instruction file support. One-liner paste for everything else.
